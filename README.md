# Front camera for the Lenovo ThinkSmart View (CD-18781Y) on mainline Linux

A V4L2 driver and device tree changes that make the built-in front camera
(Samsung **S5KC505A**, 5 MP) work on postmarketOS with the mainline-based
msm8953 kernel. Images go through the Qualcomm CAMSS raw path and libcamera's
software ISP, so the camera shows up in PipeWire and in GNOME Snapshot.

Tested on postmarketOS v26.06 (Phosh), kernel `7.0.9-msm8953`, libcamera 0.7.1.

## Status

| | |
|---|---|
| Sensor detection (chip ID `0x5034`) | works |
| Raw capture, 2-lane MIPI CSI-2, RAW10 GRBG | works, verified with the sensor's colour-bar test pattern |
| libcamera (simple pipeline + software ISP) | works, about 30 fps at 1304x980 |
| PipeWire / GNOME Snapshot | works (see the notes on rotation and rendering below) |
| Full resolution 2608x1960 | works, but the software ISP only manages about 15 fps |
| Image tuning (lens shading, colour matrix) | not done |

## Hardware details

Taken from the stock Android device tree and Lenovo's vendor sensor library:

| | |
|---|---|
| Sensor | Samsung S5KC505A, front, 2608x1960, SMIA++/CCS-style registers |
| Bus | CCI master 0, 7-bit address `0x37`, 16-bit register addresses |
| CSI | CSIPHY0 / CSID0, 2 data lanes, 960 Mbps per lane (link frequency 480 MHz) |
| Clock | MCLK0 on GPIO 26, 24 MHz |
| Reset / standby | GPIO 40 / GPIO 39, both active low |
| Supplies | VIO pm8953_l6 1.8 V; VANA pm8953_l17 2.8 V gated by GPIO 119; VDIG pm8953_l2 1.2 V gated by GPIO 118 |
| Timing | vt pixel clock 190 MHz, line length 3112, frame length 2030 (30 fps) |

## What is in here

- `driver/s5kc505a.c`: the sensor driver. Modes: 1304x980 (2x2 binned, default) and
  2608x1960 (module parameter `full_res=1`). Controls: exposure, analogue and digital
  gain, vertical blanking, test pattern.
- `driver/s5kc505a_regs.h`: init and mode register tables, generated by
  `tools/gen_regs.py` from `libmmcamera_s5kc505a.so` in the stock Android vendor
  partition. The script documents where each table lives in that file.
- `dts/camera-s5kc505a.dtsi` and `dts/patch_dtb.py`: enable CAMSS and CCI, and add the
  sensor, its supplies and the CSI link. The patch is applied to the stock DTB that
  postmarketOS ships, so no kernel tree is needed for it.
- `scripts/install-device.sh`: installs the module and the patched DTB, and keeps a
  backup of the boot config (`--undo` restores it).
- `tools/raw2png.py`: decodes MIPI-packed RAW10 captures for checking Bayer order.
- `desktop/org.gnome.Snapshot.service`: optional, see "Smooth preview in Snapshot".

## Build and install

On the device (as the normal user):

1. Build the module against a kernel build tree that matches the running kernel
   (kernel source plus the running `/proc/config.gz`, prepared with `make modules_prepare`):

   ```sh
   make -C /path/to/kernel-build ARCH=arm64 LLVM=1 M=$PWD/driver modules
   ```

2. Patch the stock DTB (needs `dtc` and `python3`):

   ```sh
   dtc -I dtb -O dts -o /tmp/stock.dts /boot/apq8053-lenovo-cd-18781y.dtb
   python3 dts/patch_dtb.py /tmp/stock.dts dts/camera-s5kc505a.dtsi > /tmp/camera.dts
   dtc -I dts -O dtb -o dts/apq8053-lenovo-cd-18781y-camera.dtb /tmp/camera.dts
   ```

3. Install and reboot:

   ```sh
   sudo sh scripts/install-device.sh
   sudo reboot
   ```

lk2nd boots the camera DTB as a separate file; the stock DTB is left untouched.
A postmarketOS kernel upgrade rewrites `extlinux.conf`, which turns the camera off
again (the system still boots). Rebuild the module and the DTB after an upgrade.

Quick check after reboot: `cam -l` (from libcamera-tools) should list
"Internal front camera".

## Notes

### Rotation

The panel is natively portrait (800x1280). Linux describes camera rotation relative
to that, so the DT uses `rotation = <180>`. Android's mount angle of 270 is relative to
its landscape default and cannot be copied.

GNOME Snapshot does not compensate for the current screen rotation: with 180 the
preview is correct in landscape (the normal way this device is used) and 90 degrees
off in portrait. Any single value can only be right in one orientation in Snapshot.

### Smooth preview in Snapshot

postmarketOS sets `GSK_RENDERER=cairo` for the Adreno 506 in
`/etc/profile.d/adreno-a506-quirks.sh`. With it, Snapshot draws the preview on the
CPU, its main thread stays at about 70% of a core and the preview stutters and
tears. With `GSK_RENDERER=gl` it uses about 18% and the preview is smooth.

To change it for Snapshot only, copy `desktop/org.gnome.Snapshot.service` to
`~/.local/share/dbus-1/services/` and restart Snapshot. Delete the file to go back.

The quirk exists because GTK's GL renderer was reported to crash more on the A506
(GTK issue 6576). No problems showed up in testing, but if Snapshot crashes or draws
garbage, remove the override.

### Frame rate

The sensor runs at 30 fps in both modes. At 2608x1960 the software ISP output is
limited to about 15 fps, so the binned mode is the default.
